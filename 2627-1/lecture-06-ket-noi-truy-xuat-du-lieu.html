2.
Đọc file đúng cách

read_csv có ~50 tham số — bạn chỉ cần thuộc 5.

Bộ 5 tham số đáng thuộc của read_csv


df = pd.read_csv(
    "listings.csv.gz",                  # nén gz? đọc thẳng, khỏi giải
    usecols=["id", "price", "host_since", "room_type"],
    parse_dates=["host_since"],         # cột ngày -> datetime luôn
    na_values=["N/A", ""],              # thứ gì coi là thiếu
    dtype={"id": "int64"},              # ép kiểu khi biết trước
)

usecols đáng giá nhất: bảng listings đầy đủ 90 cột — chỉ đọc 4 cột cần, nhanh và nhẹ hơn hẳn.

Đọc xong: dtype có như kỳ vọng?

pandas đoán kiểu giỏi nhưng không toàn năng: giá có $ và dấu phẩy thì đành chịu. Đây là việc của clean_price (buổi 2, buổi 5) — bạn đã có sẵn công cụ.

CSV vs Parquet: hai cách lưu bảng

CSV

  • Văn bản thuần — người đọc được.
  • Không mang kiểu: mọi lần đọc là một lần đoán lại.
  • To, đọc chậm.

Parquet

  • Nhị phân, theo cột, nén sẵn.
  • Giữ nguyên dtype — đọc lại y như lúc ghi.
  • Nhỏ + nhanh hơn nhiều lần.

Đo thật trên dữ liệu Santiago


df.to_csv("listings.csv", index=False)
df.to_parquet("listings.parquet")
            

listings.csv      3.5 MB   đọc lại:  76 ms
listings.parquet  1.4 MB   đọc lại:  18 ms
Cách làm tốt Quy ước của môn (và bài tập lớn): raw giữ nguyên dạng tải về (csv.gz); dữ liệu trung gian trong processed/ ưu tiên Parquet.

File to hơn RAM: đọc từng phần (chunk)

📖 Tự học

tong = 0
for chunk in pd.read_csv("reviews_khong_lo.csv.gz",
                         chunksize=100_000):
    tong += (chunk["date"] >= "2026-01-01").sum()

Mỗi vòng chỉ giữ 100 nghìn dòng trong RAM. Nhưng nếu thấy mình hay làm thế này — phần 4 có công cụ hợp hơn (DuckDB).

3.
Lấy dữ liệu qua API

Hỏi máy chủ một câu, nhận JSON một gói.

API = cổng hỏi đáp cho code

Code của bạn
requests.get(url, params)
→
Máy chủ
api.open-meteo.com
→
Response
JSON + status code

Trình duyệt cũng làm đúng việc này — API chỉ là phiên bản "cho chương trình đọc" thay vì cho mắt người.

Gọi thật: thời tiết Santiago


import requests

r = requests.get(
    "https://api.open-meteo.com/v1/forecast",
    params={"latitude": -33.45, "longitude": -70.66,
            "daily": "temperature_2m_max", "timezone": "auto"},
    timeout=20,
)
r.status_code
            

200

params = phần sau dấu ? trên URL, để requests tự mã hoá. 200 = OK; 404 = sai địa chỉ; 429 = gọi quá dày.

JSON → DataFrame


d = r.json()                      # dict lồng nhau (bài 2!)

thoi_tiet = pd.DataFrame(d["daily"])

Phép lịch sự khi gọi API


for thanh_pho in ds_thanh_pho:
    r = requests.get(URL, params=..., timeout=20)
    r.raise_for_status()          # lỗi thì dừng ngay, đừng im
    ket_qua.append(r.json())
    time.sleep(1)                 # giãn nhịp, tránh gọi quá dày
Cẩn thận Thiếu timeout — code treo vô hạn khi mạng nghẽn. Thiếu sleep — dính 429 hoặc bị chặn IP. Cả hai lỗi đều thuộc kiểu "ở nhà chạy được, lúc cần thì hỏng".

Lưu response thô = giữ bằng chứng

  • API là nguồn dữ liệu sống: hôm nay hỏi có thể khác ngày mai. Ghi JSON thô vào data/raw/ kèm ngày giờ.
  • Pipeline đọc lại từ file đã lưu — chạy lại không cần gọi mạng, kết quả bất biến.
Quan trọng "Tải một lần, xử lý nhiều lần." Đúng tinh thần cache của buổi 11 và yêu cầu tái lập của bài tập lớn.

API cần khoá (API key)

  • Nhiều API yêu cầu API key để tính quota — như Gemini ở buổi 11.
  • Key đọc từ biến môi trường / Colab Secrets, không viết vào code, không commit — quy tắc đã nêu ở buổi 1, nhắc lại vì sắp dùng thật.

4.
SQL & DuckDB

Ngôn ngữ truy vấn bảng phổ biến nhất — chạy ngay trong notebook.

Vì sao phải biết SQL?

  • Dữ liệu của mọi tổ chức nằm trong cơ sở dữ liệu — cửa vào là SQL.
  • Cùng tư duy bạn đã có: lọc, nhóm, nối — chỉ khác cách viết.
  • Đề cương môn (CLO4) yêu cầu đọc–viết được truy vấn cơ bản.

SQL ↔ pandas: cùng nghĩa, khác vỏ

SQL pandas
SELECT name, price FROM listings df[["name", "price"]]
WHERE price < 50000 df[df["price"] < 50000]
GROUP BY room_type df.groupby("room_type")
JOIN vung USING (quan) df.merge(vung, on="quan")
ORDER BY price DESC LIMIT 5 df.nlargest(5, "price")

Bạn không học tư duy mới — bạn học cách viết khác của lọc–nhóm–nối quen thuộc.

DuckDB: CSDL phân tích trong notebook


import duckdb

duckdb.query("""
    SELECT room_type,
           median(price) AS gia_trung_vi,
           count(*)      AS n
    FROM 'listings.csv'          -- query THẲNG file!
    GROUP BY room_type
    ORDER BY gia_trung_vi DESC
""").df()
            

         room_type  gia_trung_vi      n
0       Hotel room      117138.5     56
1  Entire home/apt       64900.0  15004
2     Private room       34235.0   3413
3      Shared room       20541.0     61

Không cần server, không cần import — FROM 'file.csv' chạy được ngay, Parquet cũng vậy.

Cùng đáp số với pandas — tự kiểm chứng chéo

  • Bảng slide trước ra đúng từng con số với df.groupby("room_type")["price"].median() của buổi 4.
  • Hai công cụ độc lập, một đáp số — đó chính là một cách kiểm chứng (dùng được cả với code AI viết!).

JOIN trong SQL


duckdb.query("""
    SELECT v.vung, median(l.price) AS gia
    FROM 'listings.csv' AS l
    LEFT JOIN vung_df AS v USING (neighbourhood)
    GROUP BY v.vung
""").df()

DuckDB nhìn thấy cả DataFrame trong notebook (vung_df) — trộn SQL và pandas thoải mái. Dòng NULL = các quận chưa khớp (như merge!).

Khi nào dùng gì?

Tình huống Chọn
Bảng vừa RAM, biến đổi linh hoạt, vẽ biểu đồ pandas
File to hơn RAM, tổng hợp/JOIN nặng DuckDB (rồi kết quả nhỏ → pandas)
Dữ liệu nằm sẵn trong CSDL của tổ chức SQL trên CSDL đó

Không phải chọn phe — là phân công đúng việc: bảng reviews 690 nghìn dòng của bài tập lớn hợp DuckDB; bảng KPI 50 dòng hợp pandas.

Tổng kết

  • Giữ nguyên dữ liệu raw — mọi biến đổi qua code, kết quả ghi ra chỗ khác.
  • read_csv: thuộc usecols, parse_dates, na_values, dtype (và đọc thẳng file nén); dữ liệu trung gian ưu tiên Parquet.
  • API: params + timeout + raise_for_status + sleep; lưu response thô.
  • SQL là cách viết khác của lọc–nhóm–nối; DuckDB query thẳng file ngay trong notebook.

Làm việc với AI thì sao?

🤖 Làm việc với AI
AI làm tốt Viết truy vấn SQL từ mô tả tiếng Việt; dịch pandas ↔ SQL; tra cứu tham số read_csv.
AI hay sai Bịa cấu trúc JSON của API chưa từng thấy (phải in r.json() thật ra xem); quên timeout/sleep; viết query cho schema không tồn tại.

Kiểm chứng thế nào?

🤖 Làm việc với AI
  • In response thật (r.json()) trước, đưa mẫu thật cho AI sau — đừng để nó đoán schema.
  • Query SQL quan trọng: tính lại bằng pandas (hoặc ngược lại) — hai công cụ một đáp số.
