2.
Đọc file đúng cách

Tập trung vào năm tham số thường dùng của read_csv.

Năm tham số read_csv thường dùng


df = pd.read_csv(
    "listings.csv.gz",            # đọc trực tiếp file .gz
    usecols=["id", "price", "host_since", "room_type"],
    parse_dates=["host_since"],   # chuyển cột ngày sang datetime
    na_values=["N/A", ""],        # các biểu diễn được xem là thiếu
    dtype={"id": "int64"},        # khai báo kiểu khi biết trước
)

usecols chỉ đọc các cột cần thiết. Với bảng listings có 90 cột, ví dụ này chỉ tải bốn cột vào bộ nhớ.

Mã tải dữ liệu và ví dụ đầy đủ nằm trong notebook Bài 6.

CSV vs Parquet: hai cách lưu bảng

CSV

  • Văn bản thuần — người đọc được.
  • Không mang kiểu: mọi lần đọc là một lần đoán lại.
  • To, đọc chậm.

Parquet

  • Nhị phân, theo cột, nén sẵn.
  • Lưu thông tin dtype cùng dữ liệu.
  • Thường nhỏ hơn và đọc nhanh hơn CSV.

Đo trên dữ liệu Santiago


df.to_csv("data/processed/listings.csv", index=False)
df.to_parquet("data/processed/listings.parquet")
            

listings.csv      1.4 MB   đọc lại:   9 ms
listings.parquet  0.4 MB   đọc lại:   1 ms
Cách làm tốt Trong học phần, dữ liệu gốc được giữ nguyên ở định dạng tải về (csv.gz); dữ liệu trung gian trong processed/ ưu tiên Parquet.

File lớn hơn RAM: đọc từng phần (chunk)

📖 Tự học

tong = 0
for chunk in pd.read_csv("reviews_lon.csv.gz",
                         chunksize=100_000):
    tong += (chunk["date"] >= "2026-01-01").sum()

Mỗi vòng chỉ giữ 100 nghìn dòng trong RAM. Với các thao tác tổng hợp thường xuyên trên file lớn, DuckDB ở phần 4 có thể phù hợp hơn.

API cung cấp dữ liệu có cấu trúc để chương trình xử lý, thay vì giao diện được thiết kế chủ yếu cho người dùng.

Thực hành: thời tiết Santiago


import requests

r = requests.get(
    "https://api.open-meteo.com/v1/forecast",
    params={"latitude": -33.45, "longitude": -70.66,
            "daily": "temperature_2m_max", "timezone": "auto"},
    timeout=20,
)
r.status_code
            

200

params = phần sau dấu ? trên URL, để requests tự mã hoá. 200 = thành công; 404 = không tìm thấy tài nguyên; 429 = gửi quá nhiều yêu cầu.

JSON → DataFrame


d = r.json()                      # từ điển lồng nhau

thoi_tiet = pd.DataFrame(d["daily"])

JSON phẳng có thể truyền trực tiếp vào pd.DataFrame; dữ liệu lồng nhiều tầng có thể dùng pd.json_normalize.

Các biện pháp an toàn khi gọi API


for thanh_pho in ds_thanh_pho:
    r = requests.get(URL, params=..., timeout=20)
    r.raise_for_status()      # phát sinh ngoại lệ nếu HTTP báo lỗi
    ket_qua.append(r.json())
    time.sleep(1)             # tạo khoảng nghỉ giữa các yêu cầu
Cẩn thận Nếu thiếu timeout, yêu cầu có thể chờ quá lâu khi kết nối gặp sự cố. Nếu gọi liên tục mà không tạo khoảng nghỉ, máy chủ có thể trả mã 429 hoặc giới hạn truy cập.

Lưu response thô để hỗ trợ tái lập

  • API là nguồn dữ liệu sống: hôm nay hỏi có thể khác ngày mai. Ghi JSON thô vào data/raw/ kèm ngày giờ.
  • Pipeline đọc lại từ file đã lưu để không phải gọi mạng và giữ đầu vào nhất quán.
Quan trọng Lưu dữ liệu một lần và xử lý nhiều lần. Cách làm này hỗ trợ tái lập kết quả và sẽ được dùng lại khi làm việc với API ở buổi 11.

API cần khoá (API key)

  • Nhiều API yêu cầu API key để tính quota — như Gemini ở buổi 11.
  • Khóa API được đọc từ biến môi trường / Colab Secrets, không viết vào code, không commit vào kho mã nguồn — theo quy tắc đã nêu ở buổi 1.

4.
SQL & DuckDB

Ngôn ngữ truy vấn bảng phổ biến nhất — chạy ngay trong notebook.

Vì sao phải biết SQL?

  • Nhiều tổ chức lưu dữ liệu trong cơ sở dữ liệu và truy xuất bằng SQL.
  • Các thao tác lọc, nhóm và nối có cách biểu đạt tương ứng trong SQL.
  • Môn học này yêu cầu đọc–viết được truy vấn cơ bản.

SQL ↔ pandas: thao tác tương ứng

SQL pandas
SELECT name, price FROM listings df[["name", "price"]]
WHERE price < 50000 df[df["price"] < 50000]
GROUP BY room_type df.groupby("room_type")
JOIN vung USING (quan) df.merge(vung, on="quan")
ORDER BY price DESC LIMIT 5 df.nlargest(5, "price")

Các thao tác lọc, nhóm và nối quen thuộc trong pandas có thể được biểu diễn bằng SQL.

DuckDB: cơ sở dữ liệu phân tích trong notebook


import duckdb

duckdb.query("""
    SELECT room_type,
           median(price_num) AS gia_trung_vi,
           count(*)      AS n
    FROM 'data/processed/listings.parquet'
    GROUP BY room_type
    ORDER BY gia_trung_vi DESC
""").df()
            

         room_type  gia_trung_vi      n
0       Hotel room      117138.5     56
1  Entire home/apt       64900.0  15004
2     Private room       34235.0   3413
3      Shared room       20541.0     61

Không cần vận hành máy chủ cơ sở dữ liệu riêng. DuckDB có thể đọc trực tiếp file CSV hoặc Parquet trong mệnh đề FROM.

Đối chiếu kết quả với pandas

  • Kết quả ở slide trước trùng với df.groupby("room_type")["price_num"].median() trong pandas.
  • Đối chiếu kết quả từ hai công cụ độc lập là một cách kiểm chứng, kể cả khi mã được tạo với sự hỗ trợ của AI.

JOIN trong SQL


duckdb.query("""
    SELECT v.vung, median(l.price_num) AS gia
    FROM 'data/processed/listings.parquet' AS l
    LEFT JOIN vung_df AS v USING (neighbourhood_cleansed)
    GROUP BY v.vung
    ORDER BY gia
""").df()
            

        vung        gia
0  Trung tâm  47755.165
1       NULL  57687.750
2       Đông  76628.250

DuckDB có thể truy vấn DataFrame đang tồn tại trong notebook (vung_df). Giá trị NULL tương ứng với các quận không khớp khi nối bảng.

Khi nào dùng gì?

Tình huống Chọn
Bảng vừa RAM, biến đổi linh hoạt, vẽ biểu đồ pandas
File lớn hơn RAM, cần tổng hợp hoặc JOIN DuckDB (rồi kết quả nhỏ → pandas)
Dữ liệu nằm sẵn trong CSDL của tổ chức SQL trên CSDL đó

Lựa chọn công cụ phụ thuộc vào quy mô và thao tác: DuckDB phù hợp với bảng reviews khoảng 690 nghìn dòng; pandas thuận tiện với bảng KPI nhỏ.

Tổng kết

  • Giữ nguyên dữ liệu gốc — mọi biến đổi qua code, kết quả ghi ra vị trí khác.
  • read_csv: usecols, parse_dates, na_values, dtype và khả năng đọc trực tiếp file nén; dữ liệu trung gian ưu tiên Parquet.
  • API: params + timeout + raise_for_status + sleep; lưu response thô.
  • SQL biểu diễn các thao tác lọc–nhóm–nối; DuckDB truy vấn trực tiếp file ngay trong notebook.

Kiểm chứng thế nào?

🤖 Làm việc với AI
  • Kiểm tra response thật bằng r.json(), sau đó cung cấp mẫu cho AI để tránh suy đoán sai schema.
  • Với truy vấn SQL quan trọng, tính lại bằng pandas (hoặc ngược lại) và kiểm tra hai kết quả có khớp nhau không.
